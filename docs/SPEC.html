1. Overview & mental model

A flightplan flow is a TOML file describing a browser task as an ordered list of steps, each carrying assertions. The runner executes each step through a layered cost ladder, self-heals selector drift by consulting a committed lock file, and validates outcomes with deterministic and AI assertions.

What it is

You author intent (click "the delete icon", assert text "Welcome, Ada!") rather than brittle selectors. flightplan resolves that intent to a concrete DOM element using the cheapest technique that works, remembers the winning technique in a lock file, and replays it for free on the next run. When the page drifts, it climbs a ladder of increasingly expensive strategies — deterministic first, AI only as a last resort.

Key invariants

  • Dependency inversion, everywhere. The runner talks to a Driver interface, not to browser-pilot. The ladder talks to ctx.ai? hooks, not to the AI SDK. Assertions call an injected aiJudge seam. browser-pilot and the AI SDK each live behind exactly one file (src/driver/browser-pilot-driver.ts:12 and src/ai/provider.ts). This makes the whole system testable against MockDriver and a fake GenerateFn — no Chrome, no network.
  • "Steps self-heal; assertions validate." The ladder is allowed to adapt, re-resolve, and rewrite the lock file to keep a step working. The assertion engine only reports — it never heals, never re-resolves, and never touches the lock. Correctness and adaptivity are kept in separate lanes.
  • AI-less runs are deterministic. Without OPENROUTER_API_KEY, no AI runtime is built and the run is byte-identical to the deterministic baseline (L0/L1 only). The example flows are designed to resolve at L0/L1 and need no key.
  • Types derive from zod. Schemas are the source of truth; TypeScript types are z.infer of them.

Routing

Normal path: L1 → L2 → L3 → L4. The AI climb is bounded to 3 hops :184. tier_hint="vision" skips L2 (nextAiHook :74); --start-tier l3 skips L0 and L1 :108. On a clean L0 miss, L1 reuses the shared snapshot; after an L0 replay-then-fail, L1 takes a fresh snapshot :156.

L0 detail

Trust requires both urlGlobMatches and signatureMatches(cached.sig, current, mode) where mode = ctx.cache?.signature ?? "full". buildReplayPlan l0.ts:263 produces one of: ANCHORED (primary uniquely resolves → lead + same-element fallbacks), COMPOUND (precise CSS primary alone), or DRIFT-HEAL (race the portfolio). On a signature MISS, if the primary selector still resolves, L0 replays anyway and marks revalidated=true (l0_revalidated note) — so even --frozen can pass a stale signature when the selector still resolves. An actionability gate (classifyReplaySelector :430) demotes selectors that match >1 element or resolve to a disabled control, and a safety net :170 rejects replay acting on a known-different element.

L1 detail

One snapshot, a pre-action signature basis, ranking via driver.resolveAll(intent, {snapshot, action, minConfidence:0}). The ordered strategy array is author hints + the ladder (buildStrategyArray), acted on via driver.batch; the winner and a durable (non-ref:eN) selector are learned from selectorUsed. Iframe guard :318: a plain-CSS hint matching 0 elements is probed via locateSelectorFrame; if iframe-bound it fails hard with escalate:false. Escalation requires succeeded && !ambiguous; ambiguity uses isAmbiguous(ranked,{gap:0.1}) unless the winner is a testid. Minimum score 0.4.

Strategy ladder

strategy-array.ts:243: ref:eN (this-cycle only) → testid → role_name (role:Role:Name / role:Role[N]) → label → scoped_text (interactive-role only). structural_fingerprint is a durable last resort and is never a live batch entry. The [resolve] attributes hook rides the testid tier.

L5 path-repair planner

Documentation discrepancy The L5 planner is DISABLED by default (opt-in). This is authoritative: src/config/resolve.ts sets the default to disabled, src/config/schema.ts defaults [plan] enabled to false, and README.md, docs/KNOWN_ISSUES.md, and docs/PERFORMANCE.md agree. The planner must be turned on with [plan] enabled = true (which additionally requires an AI runtime, i.e. OPENROUTER_API_KEY).

When enabled, the planner (src/ai/planner-l5.ts, glued through src/runner/path-repair.ts) proposes synthetic repair steps. Triggers: path divergence (maybeRepairPath runner.ts:1206) and an L4 intent_changed verdict :1148. runPathRepair :181 allows ≤3 attempts, escalating from a cheap planRepair to planRepairEscalated when confidence ≤0.5 or attempt ≥2. Proposed steps are validated against StepSchema, given ids <id>:repair:<a>.<i>, spliced in after the cursor, counted against max_steps, and refused for lock write-back. Prompt caching is mandatory (uncached ~3.85× cost): a stable prefix (goal + vocabulary) plus a volatile suffix (page + recent actions, bounded to 8). Any failure degrades to "no repair".

Target syntax

A target is either a bare natural-language query (prose → resolved by the ladder) or a prefixed selector. The whitelist of prefixes is ref:, role:, text:, css:, or a leading [ (src/flow/normalize-target.ts:20–73). A target may be an array: earlier entries are author hints, later entries fallbacks. Example (wizard.toml):

[[steps]]
id = "name"
fill = true
target = ["[data-testid='wizard-name']", "the full name field"]
value = "${inputs.full_name}"

Pure prose targets route straight to vision when hinted, e.g. vision.toml:

target = "the trash-can / delete icon in the toolbar to delete the item"
tier_hint = "vision"

on_fail

for_each macro

A load-time macro (src/flow/normalize.ts), not in the schema. A step with for_each = [...] (strings or string-valued tables) expands to N steps with ids <base-id>#<1-based-idx>. Loop tokens: ${item}, ${item.key}, ${loop.index} (0-based), ${loop.index1}. A loop token on a non-for_each step is a hard error.

Templating

src/flow/template.ts: ${inputs.<name>} and ${env.<NAME>}, whitespace-tolerant regex :43, applied deep to every string leaf. An undeclared input or unset env var throws TemplateError; an unknown source throws. Loop tokens are a separate, load-time concern. For run-step composition, with values are templated against the parent scope and win over child defaults (resolveInputs :257–287).

Per-flow *.lock.toml sidecars are committed source artifacts. LOCK_VERSION = 2 (src/lock/types.ts:212). Serialization is byte-identical (deterministic), and v1 files auto-migrate on load.

Scoring & portfolio

scoreEntry src/lock/portfolio.ts:106 = greens × 2^(-ageDays/30); a drift-capped entry (last_drift ≥ last_ok) is multiplied by 0.1. Constants: HALF_LIFE = 30d, STALE = 90d, K_MAX = 6. Kind priority: testid > role_name > label > scoped_text > css > structural_fingerprint. rankPortfolio :186 is deterministic. Write-back flows through session.recordResolution src/lock/session.ts:178 → decideLockWrite src/lock/write.ts:276; applyOutcome :392 handles agreed (greens+1, last_ok), drifted (last_drift), and learned (greens:1). A "heal" is defined narrowly as the top winner changing.

Write modes

resolveLockWriteMode src/lock/write.ts:181:

  • --frozen → frozen: never write; drift FAILS the run (CI mode). Beats --no-lock-write.
  • --no-lock-write → no-write.
  • otherwise → auto: an L0 hit refreshes track records / signature; a real heal (winner changed) persists only in auto.

Invariants

  • Selectors are never ref:eN — assertDurableSelector recipe.ts:38 throws on ephemeral refs.
  • A revalidated (stale-sig) hit refreshes only match + last_seen.
  • Memory notes are persisted only from a corroborated pick or one with confidence ≥0.8 (NOTE_CONFIDENCE_MIN), redacted and decayed.
  • ai_pick round-trips kind + pinned_choice; a nameless icon pins to [data-cmd] or role:Role[N] for zero-AI warm replay.

ai_pick

A step verb (not an assertion). It picks one element from a set given intent, then pins the choice into the lock (pinned_choice) so subsequent warm runs replay at L0 with zero AI.

Vision batching

resolveBatchL3 src/ai/vision-l3.ts:300 + orchestrator resolveVisionBatch orchestrator.ts:231: ≥2 same-page hinted steps collapse into 1 screenshot + 1 keyed call (~79.5% cheaper, ~74.7% faster). The response envelope is lenient ({picks:[unknown]}) with per-pick re-validation (indexByKey :385); a malformed pick falls back to its own single L3 call. A step carrying its own assert or on_fail is not batched.

Prompts-by-index design

L2/L3 packets number candidates by index and present role + name + score + ancestor context — never raw selectors. The model returns an index (or screenshot_needed / give_up), which the ladder maps back to a concrete element. This keeps the model out of the business of inventing selectors and makes every AI decision re-validatable against the live snapshot.

9. Drift detection & page signatures

Portfolio race

racePortfolio (src/lock/revalidate.ts:286) resolves each durable selector and runs an identity check over one snapshot. Outcomes: Agreement (≥2 strategies hit the same element), Single, Disagreement (prefer the track-record winner corroborated by role + name), or None → miss → fall to L1. The trace records the strategy and agreement ratio (e.g. "3/4").

Page signatures

capturePageSignature (src/ladder/page-signature.ts) builds the composite text:<textSig>;struct:<structSig>. The text signature is a volatile-masked hash (excluding aria-live, data-live, hidden nodes, and [cache] ignore_regions). The struct signature is a role-tree hash. Signature mode (full vs struct-only) is set per-step via cache or globally via [cache] signature.

Path divergence

detectDivergence (src/runner/path-repair.ts:101): after a mutating step, compare the current signature against the next step's match.sig. No expectation → null. Only the mutating verbs (goto, click, fill, select, ai_pick) participate. A divergence is one of the two triggers for the (opt-in) L5 planner.

12. Errors, retries, budgets, timeouts

Verdicts & budgets

Retries

  • Model-level: the fallback chain in defaultGenerate.
  • Step-level: on_fail goto/max ("self" retries) rolls back the failure state; heals are not rolled back and cannot cross a run boundary.
  • Infrastructure: a run-level error is not recoverable. There is no mid-run reconnect — a CDP drop is an error, exit 2.

Timeouts

[timeouts] (schema.ts:311, resolved resolve.ts:78): action_ms 5000, nav_ms 2000, settle_ms 150, ai_call_ms role-aware; assertions use assert_timeout_ms 5000. A step's own timeout_ms wins over action_ms.

13. Performance & known issues

Benchmark headlines

From BENCHMARK.md: tiered cost ladder vs a vision-only "standard loop", over 9 flows × 3 trials (27 runs each). WARM (learned locks in place) vs BASELINE:

  • 5.52× faster wall-clock (48.4s vs 267.2s).
  • 4.85× cheaper ($0.006078 vs $0.029473); 6.13× cheaper per pass.
  • 4.8× fewer AI calls (10 vs 48); 35× fewer vision calls (1 vs 35).
  • 12.8× faster step latency p50 (190ms vs 2432ms); 6.2× faster p95.
  • 93.3% of steps resolve free at L0/L1 vs 0% for the baseline.
  • More reliable: 24/27 pass vs 19/27; excluding the by-design contexts failure, 24/24 (100%) vs 19/24 (79%).

Even COLD (first run, learning from scratch) the ladder beats the baseline ~2.8× cheaper / ~3.3× faster, and that run writes the locks the warm runs consume. The vision flow's cold-L3 → warm-L0 transition is a 28.9× speedup. contexts fails by design (iframe). gauntlet shows no warm benefit — its recipe is not L0-replayable (a known follow-up).

Known issues

From docs/KNOWN_ISSUES.md:

  • No checked / enabled assert type. Assert on a value/text proxy or use ai_judge. (Note: the earlier limitation on selector/CSS asserts against non-interactive nodes is FIXED — those now resolve via elementState.)
  • Occluded elements need vision. An element present in the DOM but visually hidden may still report present via elementState; confirming true perceivability needs an ai_judge vision check.
  • The L5 planner is opt-in (see the callout in §4).
  • Iframes are not pierced — L1 fails fast on iframe-bound targets.
  • A mid-run crash is exit 2 with no reconnect.
