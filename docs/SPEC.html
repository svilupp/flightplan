1. Overview & mental model

A flightplan flow is a TOML file describing a browser task as an ordered list of steps, each carrying assertions. The runner executes each step through a layered cost ladder, self-heals selector drift by consulting a committed lock file, and validates outcomes with deterministic and AI assertions.

What it is

You author intent (click "the delete icon", assert text "Welcome, Ada!") rather than brittle selectors. flightplan resolves that intent to a concrete DOM element using the cheapest technique that works, remembers the winning technique in a lock file, and replays it for free on the next run. When the page drifts, it climbs a ladder of increasingly expensive strategies — deterministic first, AI only as a last resort.

Key invariants

  • Dependency inversion at the runtime seams. The runner talks to a Driver interface, not to browser-pilot. The ladder talks to ctx.ai? hooks, not to the AI SDK. Assertions call an injected aiJudge seam. The browser-pilot runtime adapter is src/driver/browser-pilot-driver.ts; type and compatibility imports also live in the driver boundary/support files and src/ai/resolve-common.ts. The AI SDK runtime imports remain in src/ai/provider.ts. This makes the whole system testable against MockDriver and a fake GenerateFn — no Chrome, no network.
  • "Steps self-heal; assertions validate." The ladder is allowed to adapt, re-resolve, and rewrite the lock file to keep a step working. The assertion engine only reports — it never heals, never re-resolves, and never touches the lock. Correctness and adaptivity are kept in separate lanes.
  • AI-less runs have no AI runtime. Deterministic-only flows can run at L0/L1 without OPENROUTER_API_KEY; AI calls are unavailable without a key, so flows that require L2/L3/L4 or ai_judge cannot complete.
  • Types derive from zod. Schemas are the source of truth; TypeScript types are z.infer of them.

Routing

Normal path: L1 → L2 → L3 → L4. The AI climb is bounded to 3 hops :198. tier_hint="vision" skips L2 (nextAiHook :84); --start-tier l3 skips L0 and L1 :118. On a clean L0 miss, L1 reuses the shared snapshot; after an L0 replay-then-fail, L1 takes a fresh snapshot :169.

L0 detail

Trust requires both urlGlobMatches and signatureMatches(cached.sig, current, mode) where mode = ctx.cache?.signature ?? "full". buildReplayPlan l0.ts:334 produces one of: ANCHORED (primary uniquely resolves → lead + same-element fallbacks), COMPOUND (precise CSS primary alone), or DRIFT-HEAL (race the portfolio). On a signature MISS, if the primary selector still resolves, L0 replays anyway and marks revalidated=true (l0_revalidated note) — so even --frozen can pass a stale signature when the selector still resolves. An actionability gate (classifyReplaySelector :501) demotes selectors that match >1 element or resolve to a disabled control, and a safety net :226 rejects replay acting on a known-different element.

L1 detail

One snapshot, a pre-action signature basis, ranking via driver.resolveAll(intent, {snapshot, action, minConfidence:0}). The ordered strategy array is author hints + the ladder (buildStrategyArray), acted on via driver.batch; the winner and a durable (non-ref:eN) selector are learned from selectorUsed. Iframe guard :393: a plain-CSS hint matching 0 elements is probed via locateSelectorFrame; if iframe-bound it fails hard with escalate:false. Escalation requires succeeded && !ambiguous; ambiguity uses isAmbiguous(ranked,{gap:0.1}) unless the winner is a testid. Minimum score 0.4.

Strategy ladder

After switch_frame enters a same-origin iframe, the current frame is allowed and subsequent in-frame targets resolve successfully. A direct target inside an unentered same-origin iframe still fails fast through the L1 iframe guard instead of acting on a look-alike parent.

strategy-array.ts:243: ref:eN (this-cycle only) → testid → role_name (role:Role:Name / role:Role[N]) → label → scoped_text (interactive-role only). structural_fingerprint is a durable last resort and is never a live batch entry. Explicit author hints may also be classified as css. The [resolve] attributes hook rides the testid tier.

L5 path-repair planner

Default The L5 planner is DISABLED by default (opt-in). This is authoritative: src/config/resolve.ts sets the default to disabled, src/config/schema.ts defaults the internal plan.enabled to false, and README.md agrees. In a flow file, turn it on with [config.plan] enabled = true (which additionally requires an AI runtime, i.e. OPENROUTER_API_KEY).

When enabled, the planner (src/ai/planner-l5.ts, glued through src/runner/path-repair.ts) proposes synthetic repair steps. Triggers: path divergence (maybeRepairPath) and an L4 intent_changed verdict. runPathRepair :181 allows ≤3 attempts, escalating from a cheap planRepair to planRepairEscalated when confidence ≤0.5 or attempt ≥2. Proposed steps are validated against StepSchema, given ids <id>:repair:<a>.<i>, spliced in after the cursor, counted against max_steps, and refused for lock write-back. Prompt caching is mandatory (uncached ~3.85× cost): a stable prefix (goal + vocabulary) plus a volatile suffix (page + recent actions, bounded to 8). The uncached incremental-planning probe measured 2.51× full-plan cost and 4.35× full-plan tokens. Any failure degrades to "no repair".

Target syntax

A target is either a bare natural-language query (prose → resolved by the ladder) or a prefixed selector. The whitelist of prefixes is ref:, role:, text:, css:, or a leading [ (src/flow/normalize-target.ts:20–73). A target may be an array: earlier entries are author hints, later entries fallbacks. Example (wizard.toml):

[[steps]]
id = "name"
do = "fill"
target = ["[data-testid='wizard-name']", "the full name field"]
value = "${inputs.full_name}"

css: is a Flightplan authoring prefix and is stripped at the driver boundary. Browser-pilot accepts both role:button:Next and role:button[name="Next"]. fingerprint:/fp:/structure: are internal lock identity tokens, not executable target selectors; label: is not part of the target contract.

Pure prose targets route straight to vision when hinted, e.g. vision.toml:

target = "the trash-can / delete icon in the toolbar to delete the item"
tier_hint = "vision"

Runtime captures and popup expectations

A step may capture a URL, text, value, or state into a named runtime value. Later step fields use ${capture.name}; the value is resolved when that step runs and is redacted in artifacts. A step may also declare expect_page, popup, or new_page with optional url, title, type, target_id, opener, and timeout_ms. The runner arms popup observation before dispatch and records a mismatch as an ambiguous transport result.

Effects and retry safety

effect declares the side-effect contract: observe, idempotent, or at_most_once. Browser actions carry dispatch evidence (not_dispatched, dispatched, or uncertain) and retry metadata into the trace and summary. on_fail may jump only when the action is safe to re-enter; dispatched or uncertain actions, at_most_once steps, and retry.policy = "never" block redispatch. A possible at-most-once effect without a passing postcondition yields inconclusive rather than a second attempt.

on_fail

OnFailSchema :190: {goto: string, max?: int} - jump to a step id or "self" (retry); max defaults to 1. A permitted jump rolls back the failure state (heals are not rolled back) and cannot cross a run boundary.

for_each macro

A load-time macro (src/flow/normalize.ts), not in the schema. A step with for_each = [...] (strings or string-valued tables) expands to N steps with ids <base-id>#<1-based-idx>. Loop tokens: ${item}, ${item.key}, ${loop.index} (0-based), ${loop.index1}. A loop token on a non-for_each step is a hard error.

Templating

src/flow/template.ts: ${inputs.<name>}, ${env.<NAME>}, and runtime ${capture.<name>}, using a whitespace-tolerant regex :45, applied deep to every string leaf. An undeclared input, unset env var, or unavailable runtime capture throws TemplateError; an unknown source throws. Capture values come from earlier steps and are resolved at execution time. Loop tokens are a separate, load-time concern. For run-step composition, with values are templated against the parent scope and win over child defaults (resolveInputs :270).

Write modes

resolveLockWriteMode src/lock/write.ts:181:

  • --frozen → frozen: never write; drift FAILS the run (CI mode). Beats --no-lock-write.
  • --no-lock-write → no-write.

A step verb (not an assertion). It picks one element from a set given intent, then pins the choice into the lock (pinned_choice) so subsequent warm runs replay at L0 with zero AI.

Vision batching

resolveBatchL3 src/ai/vision-l3.ts:300 + orchestrator resolveVisionBatch orchestrator.ts:246: ≥2 same-page hinted steps collapse into 1 screenshot + 1 keyed call. The benchmark's 8-icon batch matched 8/8 in 2.77s versus 11.96s for eight single calls, 76.8% faster. The response envelope is lenient ({picks:[unknown]}) with per-pick re-validation (indexByKey :385); a malformed pick falls back to its own single L3 call. A step carrying its own assert or on_fail is not batched.

Prompts-by-index design

L2/L3 packets number candidates by index and present role + name + score + ancestor context — never raw selectors. The model returns an index (or screenshot_needed / give_up), which the ladder maps back to a concrete element. This keeps the model out of the business of inventing selectors and makes every AI decision re-validatable against the live snapshot.

9. Drift detection & page signatures

Portfolio race

racePortfolio (src/ladder/revalidate.ts:302) resolves each durable selector and runs an identity check over one snapshot. Outcomes: Agreement (≥2 strategies hit the same element), Single, Disagreement (prefer the track-record winner corroborated by role + name), or None → miss → fall to L1. The trace records the strategy and agreement ratio (e.g. "3/4").

Page signatures

capturePageSignature (src/ladder/page-signature.ts) builds the composite text:<textSig>;struct:<structSig>. The text signature is a volatile-masked hash (excluding aria-live, data-live, hidden nodes, and [cache] ignore_regions). The struct signature is a role-tree hash. Signature mode (full vs struct-only) is set per-step via cache or globally via [cache] signature.

Path divergence

detectDivergence (src/runner/path-repair.ts:101): after a mutating step, compare the current signature against the next step's match.sig. No expectation → null. Only the mutating verbs (goto, click, fill, select, ai_pick) participate; emit is excluded and never triggers divergence detection. A divergence is one of the two triggers for the (opt-in) L5 planner.

11. Driver layer

The Driver interface (src/driver/types.ts:469) is the seam used by the runner, ladder, assertions, and tests. Lifecycle: connect → page → ops → teardown. In Mode A (attach) teardown only detaches; in Mode B (launch) it detaches and kills.

Methods

  • goto / currentUrl, snapshot(opts), batch, resolveAll (native ranking).
  • Single actions returning boolean: click, fill, type, select, check, hover, press, and submit; screenshot() → base64.
  • Optional: provenance, expectNewPage, pageState, elementState, locateSelectorFrame, startRecording, stopRecording, saveScreenshot, and webmcpCall.
  • switchToFrame, switchToMain, and currentFrame for stateful frame context; clearBrowserState for isolation.
  • exportRefMap / importRefMap (refs valid for exactly one cycle).
  • captureStateSignature({mode:"text"|"structure"}).

12. Errors, retries, budgets, timeouts

Verdicts & budgets

computeVerdict runner.ts:1863 precedence: error > inconclusive > failed > passed. Budgets (src/ai/budget.ts): max_model_calls, max_screenshots, max_replans are pre-checked; max_cost_usd is post-checked. A BudgetExceededError yields inconclusive. Precedence between sections: [run] beats [ai]; max_replans in [run] beats [plan].

Retries

  • Model-level: the fallback chain in defaultGenerate.
  • Step-level: on_fail goto/max ("self" retries) rolls back the failure state; heals are not rolled back and cannot cross a run boundary.
  • Effect safety: dispatched or uncertain actions are observation-only after the input boundary. Postconditions may rescue a logically failed action without redispatching it; an unconfirmed at_most_once effect becomes inconclusive.
  • Infrastructure: a run-level error is not recoverable. There is no mid-run reconnect — a CDP drop is an error, exit 2.

Timeouts

[timeouts] (schema.ts:311, resolved resolve.ts:78): action_ms 5000, nav_ms 2000, settle_ms 150, ai_call_ms role-aware; assertions use assert_timeout_ms 5000. A step's own timeout_ms wins over action_ms.

13. Performance & known issues

Benchmark headlines

Current figures from BENCHMARK.md:

  • In the documented 54-run comparison, tiered execution passed 27/27 in 104.177s at $0.007702686; the AI-only baseline passed 24/27 in 200.530s at $0.044031.
  • The tiered arm was 1.93× faster and 5.72× cheaper than the baseline.
  • The cold flightplan-benchmarks campaign passed 27/54 runs at $0.124307; the warm tiered sweep passed 21/27 at $0.011193.
  • Warm lock reuse reached L0 on 273/279 resolving steps (97.85%), with a 98.92% deterministic share and $0.000533 cost per pass.
  • Both benchmark reports recorded zero drift, and lock stability passed.

The separate benchmark-new run passed 5/6 scenarios, kept all 34 resolving steps at L1, made zero AI calls, and cost $0. Its contexts failure was the direct fill_iframe_input target attempted before entering the iframe; the parent-mediated iframe interaction passed. Same-origin iframe targets succeed after switch_frame.

Known issues

Current limitations observed in docs/BENCHMARK.md and the implementation:

  • State assertions support enabled, disabled, checked, unchecked, and selected. Selector/CSS asserts against non-interactive nodes resolve via elementState.
  • Occluded elements need vision. An element present in the DOM but visually hidden may still report present via elementState; confirming true perceivability needs an ai_judge vision check.
  • The L5 planner is opt-in (see the callout in §4).
  • Same-origin iframe targets succeed after switch_frame. A direct target inside an unentered iframe is not reachable through the top-document snapshot; L1 fails fast instead of acting on a look-alike parent.
  • A mid-run crash is exit 2 with no reconnect.
